Menus and commands
==================

Commands, menu strips and context menus.

.. list-table::
   :class: autosummary longtable
   :widths: 35 65

   * - :cpp:class:`MenuStrip <gui_forms::MenuStrip>`
     - A window's menu bar: a row of top-level menus such as File, Edit and View.
   * - :cpp:class:`ToolStrip <gui_forms::ToolStrip>`
     - A command strip of buttons, labels, separators and drop-down buttons.
   * - :cpp:class:`RibbonFontControl <gui_forms::RibbonFontControl>`
     - A ribbon font control: a family list and a size list choosing one font.
   * - :cpp:class:`RibbonColorPicker <gui_forms::RibbonColorPicker>`
     - A ribbon drop-down colour picker: a split button over a palette overlay.
   * - :cpp:class:`BackstageView <gui_forms::BackstageView>`
     - The File tab's full page: a column of commands and topics beside the topic's page.
   * - :cpp:class:`RibbonGallery <gui_forms::RibbonGallery>`
     - A ribbon gallery: a grid of image items in categories, in the ribbon or as a drop-down.
   * - :cpp:class:`StatusStrip <gui_forms::StatusStrip>`
     - A status bar laid out as a strip of labels along the bottom of a window.
   * - :cpp:class:`QuickAccessToolbar <gui_forms::QuickAccessToolbar>`
     - The Quick Access Toolbar of a ribbon window: a small strip of command buttons the user chooses.
   * - :cpp:class:`ToolStripPanel <gui_forms::ToolStripPanel>`
     - A band along one edge that holds ToolStrips.
   * - :cpp:class:`ToolStripContainer <gui_forms::ToolStripContainer>`
     - Four ToolStripPanels around a content panel.
   * - :cpp:class:`BindingNavigator <gui_forms::BindingNavigator>`
     - A ToolStrip that moves through a BindingSource.
   * - :cpp:class:`Ribbon <gui_forms::Ribbon>`
     - A ribbon: the File tab and core tabs over a command plane of groups.
   * - :cpp:class:`ContextMenu <gui_forms::ContextMenu>`
     - An overlay menu of commands that the application opens at a point, such as on a right-click.
   * - :cpp:class:`Command <gui_forms::Command>`
     - An application action, such as Save or Copy, shared by every button, menu item and shortcut that triggers it.
   * - :cpp:class:`FontCommand <gui_forms::FontCommand>`
     - The value command of a font control: a shared Command and a font choice.
   * - :cpp:class:`ColorCommand <gui_forms::ColorCommand>`
     - The value command of a colour picker: a shared Command, a colour and the recent colours.
   * - :cpp:class:`GalleryCommand <gui_forms::GalleryCommand>`
     - The value command of a gallery: a shared Command, the chosen item, and live preview.

.. cpp:struct:: ToolStripItemSpec final

   ``#include <gui_forms/controls/tool_strip/tool_strip.hpp>``

   One item. ``stable_id`` is unique within the strip and names the item in events, semantics and the published anatomy. An item with a ``command`` takes its text (when ``text`` is empty), enabled, visible and checked state from it, and a click executes it. An item without one uses ``text``, ``enabled``, ``visible`` and the strip's own checked state. ``drop_down`` is the menu of a drop-down or split button and must be empty for other kinds. ``spring`` is honoured only by StatusStrip, on labels: spring labels share the width the other items leave. A hosted item (combo box, text box, progress bar) takes no command, menu or check. Its ``text`` is the hosted control's accessible name, ``choices`` are a combo box's items, and ``width`` its width in logical units (zero for the default: 120 for a combo box, 100 otherwise). Hosted items never move to the overflow menu, whatever their ``overflow``: a menu row cannot hold a control. The application reaches the control through combo_box(), text_box() or progress_bar(); it keeps its state while set_items keeps an item of the same ID and kind. ``tool_tip_text`` is the item's plain tooltip (owner, 2026-10-28): the window's presenter shows it over the item, and keyboard focus on the item shows it below the item; empty shows none. It reaches the item's semantic node (SemanticNode::tool_tip), and a hosted item's control as that control's tooltip text.

.. cpp:function:: std::string serialize_ribbon_state(const RibbonState& state)

   The stable text form, one entry per line, LF-terminated: gui_forms.ribbon_state 1 quick_access.placement=above_ribbon (or below_ribbon) ribbon.minimized=false (or true) quick_access.command=<command ID> (one line per ID, in order) <unrecognized entries, unchanged> Command IDs are written verbatim; an ID may not be empty or hold a line break or other control character. .. cpp:function:: RibbonState capture_ribbon_state(const QuickAccessToolbar& toolbar, bool minimized)

   The toolbar's part of the state, and its application to a toolbar. ``minimized`` is the Ribbon's, which applies it. Command IDs the toolbar does not declare survive apply and capture (the toolbar keeps them, inert); unrecognized entries are not the toolbar's, so capture returns none and a caller that keeps them copies them from the state it loaded. .. cpp:function:: bool merge_strips(ToolStrip& source, ToolStrip& target)

   Merges ``source`` into ``target``. Returns whether any item moved or left; false, changing nothing, when either strip does not allow merging, when nothing applies, or when the result would be invalid (a repeated item ID). Throws std::invalid_argument when ``source`` is ``target``, and std::bad_weak_ptr when ``source`` is not owned by a shared pointer.

.. cpp:function:: bool merge_strips(MenuStrip& source, MenuStrip& target)

.. cpp:function:: bool revert_merge(ToolStrip& target)

   Reverts every merge into ``target``, newest first, restoring the sources that still exist (items of a destroyed source are dropped from the target). Returns whether there was a merge to revert. Each merge reverts whole or not at all: when restoring one would make either strip invalid (items added since with a repeated ID), std::invalid_argument propagates, the newer merges stay reverted, and that merge and the older ones stay in place with their history.

.. cpp:function:: bool revert_merge(MenuStrip& target)

.. cpp:function:: bool revert_merge(ToolStrip& target, ToolStrip& source)

   Reverts the newest merge of ``source`` into ``target``: the merges after it are reverted first and then merged again, in their order, from the sources that still exist. Returns whether ``source`` had merged into ``target``. Failures as revert_merge(target).
