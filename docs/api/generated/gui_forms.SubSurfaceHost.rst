gui_forms::SubSurfaceHost
=========================

.. cpp:namespace:: gui_forms

.. cpp:class:: SubSurfaceHost final : public Control

   ``#include <gui_forms/surface_root/sub_surface/sub_surface_host.hpp>``

   Region control that runs one threaded sub-surface with its own retained tree, sizes and reconfigures it, composes its LiveSurface frames into the window, and forwards input and keyboard focus to it.

      Whether the host publishes the sub-surface in the window's semantic tree: its own pane and the sub-surface's nodes as its virtual children (the class comment). On by default. A control that publishes what the sub-surface draws itself (a DataGridView's cell region: the grid publishes its cells) turns it off; the host then publishes no node, takes no snapshot and performs no semantic action, and the sub-surface's own controls are reached only through its owner.

   .. rubric:: Methods

   .. cpp:function:: std::uint64_t redraw_all(std::unique_ptr<SubSurfaceContentUpdate> update)

      The parent's redraw-all (design note section 2): sends a configuration under a new content epoch carrying ``update`` (null for none), so that the sub-surface's first frame at that epoch shows it and the window composes no older frame once it pairs (section 6). Call it in the same turn as the chrome change it must agree with (a scroll, a column width). Returns the epoch the update rides: the new content_epoch(), or, while there is no content, no window or no device size yet, 0 and the update waits for the first configuration (a newer one replaces it). New content (set_content) discards a waiting update.
