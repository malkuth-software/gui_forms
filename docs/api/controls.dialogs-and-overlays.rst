Dialogs and overlays
====================

Anchored overlays, tooltips, owned dialogs and the host's file and colour dialogs.

.. list-table::
   :class: autosummary longtable
   :widths: 35 65

   * - :cpp:class:`AnchoredOverlayLayer <gui_forms::AnchoredOverlayLayer>`
     - A transparent full-window overlay that shows one overlay control next to an anchor control.
   * - :cpp:class:`FontDialog <gui_forms::FontDialog>`
     - A dialog for choosing one of GUI.Forms' bundled fonts.
   * - :cpp:class:`TaskDialog <gui_forms::TaskDialog>`
     - A message dialog of pages: heading, text, icon, buttons, choices, details and progress.
   * - :cpp:class:`ThreadExceptionDialog <gui_forms::ThreadExceptionDialog>`
     - The dialog for an exception the application did not handle.
   * - :cpp:class:`Callout <gui_forms::Callout>`
     - Non-modal teaching callout at a target control: a card with a beak pointing at the target, a title, wrapped text, a close mark and an optional action, placed below or above the target in an overlay, with optional light dismiss.
   * - :cpp:class:`ModalLayer <gui_forms::ModalLayer>`
     - In-window modal layer: any control shown centred over a scrim dimming its owner's window, taking every press outside it and holding focus, closed with a DialogResult through a cancellable closing.
   * - :cpp:class:`AboutDialog <gui_forms::AboutDialog>`
     - An application's About box: a TaskDialog preset with the information icon, the product and version, description and copyright, credits behind an expander, and OK.
   * - :cpp:class:`FolderBrowserDialog <gui_forms::FolderBrowserDialog>`
     - The host's dialog for choosing a folder.
   * - :cpp:class:`ColorDialog <gui_forms::ColorDialog>`
     - The host's dialog for choosing a color.
   * - :cpp:class:`ToolTip <gui_forms::ToolTip>`
     - The Windows Forms way to give controls short help text and to set when it shows.
   * - :cpp:class:`RibbonToolTip <gui_forms::RibbonToolTip>`
     - A provider of enhanced tooltips: a title, a description, a shortcut, an image, why a command is unavailable, and an F1 help topic.
   * - :cpp:class:`SaveFileDialog <gui_forms::SaveFileDialog>`
     - The host's dialog for choosing where to save a file.

.. cpp:function:: FileDialogFilterParse parse_file_dialog_filter(std::string_view filter)

   Parses a filter in Windows Forms' syntax, ``label|patterns|label|patterns``, where patterns are separated by ``;`` and spaces around a pattern are ignored: "Text files|*.txt;*.log|All files|*.*". ``*.extension`` becomes the host filter's extension (without the dot; ``*.tar.gz`` gives ``tar.gz``), and ``*`` and ``*.*`` become ``*``, which every host reads as any file. An empty string is no filter: the host shows every file.

.. cpp:function:: bool file_dialog_filter_matches(const HostFileDialogFilter& filter, std::string_view file_name)

   Whether a file name passes a host filter, as the portable hosts filter a directory listing: true when the filter has no extensions or holds ``*`` or ``*.*``, or when the name ends in ``.`` followed by one of its extensions. Letters compare without regard to ASCII case, so ``png`` matches ``photo.PNG`` and ``PNG`` matches ``photo.png``; a multi-dotted extension such as ``tar.gz`` matches ``backup.tar.gz``. A name that is only the extension (``.png``) does not match. Leading ``*`` and ``.`` of an extension are ignored, so a hand-built ``*.png`` or ``.png`` reads as ``png``. ``file_name`` is a name, not a path; pass file_dialog_name_part of a path.

.. cpp:function:: bool file_dialog_text_valid(std::string_view text)

   Whether ``text`` may be a dialog's title, directory or name: valid UTF-8 without NUL, of at most HostServices::maximum_dialog_text_bytes.

.. cpp:function:: std::string file_dialog_name_part(std::string_view path)

   The last component of a host path: the file's name without its directory, by the path rules of the platform the program runs on (Windows accepts ``\`` and ``/``, the others ``/`` only). Empty for a path that ends in a separator.

.. cpp:function:: MessageBoxResult show_message_box(Window& owner, const MessageBoxRequest& request)

   Shows a message box over ``owner``, modally, and returns when it closes (Windows Forms' MessageBox.Show). The host draws the box (owner decision W-Q3): MessageBoxW on Windows, NSAlert on macOS, and a dialog of GUI.Forms controls on X11, through the window's HostServices (capability ``dialogs``). TaskDialog stays the themed, richer dialog drawn in the window. The result is the chosen button. A box the user closes without choosing (Escape or the title bar's close button) returns cancel, or ok for a box whose only button is OK, as in Windows Forms; a Yes/No or Abort, Retry, Ignore box, which the user cannot close without choosing, returns none when the host closes it. The options are presentation: Windows honours both; on X11 either aligns the text to the right; macOS lays its alerts out in the system's own direction and shows the box as without them. Help: the Help button, or F1 while the box is open (with or without the button; macOS has no F1 help, so there only the button asks), raises the owner window's help_requested and then offers the request to its HelpProviders (Window::request_help); the box stays open. Its handlers run inside the host's modal loop: they may open other windows but cannot close the box. When a handler destroys the owner window or disposes a provider, later requests skip what is gone and the box still returns its result. An exception from a help handler is held and thrown by show_message_box once the box has closed. Without a host or without ``dialogs`` the result is refused, with HostServiceError::unsupported. Throws std::invalid_argument for text or a caption that is not valid UTF-8, contains NUL or is longer than HostServices::maximum_dialog_text_bytes, and for an unknown button set, icon, default button or option; throws std::logic_error off the window's UI thread.
