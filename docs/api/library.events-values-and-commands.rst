.. cpp:class:: CommandTarget final

   ``#include <gui_forms/commands/command_route/command_route.hpp>``

   The command handlers one place in the chain offers: a document's Save, a tool panel's Refresh. A target holds at most one handler per command identity. Handlers are named delegates: the target neither owns nor extends the life of their objects, so whoever owns a handler's object removes the handler, or the whole target, before that object dies. The owner of a target (usually through a shared_ptr held by a control or a docking workspace) decides its life; a window and its controls' focused route only observe it, and a destroyed target drops out of the chain. A target belongs to the UI thread of the windows that route to it and is not synchronized.


   .. rubric:: Construction

      :cpp:func:`name <gui_forms::CommandTarget::name>` identifies the target in route results and diagnostics; it may be empty.

.. cpp:namespace:: gui_forms

``#include <gui_forms/event/event/event.hpp>``

.. cpp:function:: template <typename Owner, typename Method, typename... Bound, typename... Arguments> void on(Event<Arguments...>& event, Owner& owner, Method method, Bound... bound)

   Owner-held named member subscription. Owner must explicitly participate in Component lifecycle; Target may be Owner or one of its bases. A disposed owner is a no-op; a null member is rejected even for a disposed owner. Registration may allocate/throw. Emission adds no allocation or idle work. Owner and publisher obey the existing Event execution-thread contract.

.. cpp:var:: constexpr std::size_t maximum_nested_event_emissions

   The deepest emissions may nest on one thread, across every Event: a handler that raises an event (the same one or another) nests one emission inside its own. An emission that would pass the limit is refused before any handler runs: emit returns at once and counts it in that event's EventStatistics::emissions_refused. Ordinary chains (a property change whose handler sets another property) nest a few levels; a chain that reaches the limit is a handler loop. The budget: each level is emit's frame, the slot's dispatch and the handler, 8 KiB allowed in all, so 32 levels take at most 256 KiB, half of the smallest UI-thread stack among the hosts (a macOS secondary thread's 512 KiB). Value: ``32U``.

.. cpp:function:: RuleAction invoke(Command& command)

   Executes ``command`` through the firing window's command route (Command::execute_routed), as a menu or shortcut does.

.. cpp:function:: template <typename T> RuleAction set(Value<T>& value, T written)

   Writes ``written`` to ``value`` (Value::set: an equal value does nothing, a rejected one throws and stops the firing's later actions).

.. cpp:function:: RuleAction toggle(Value<bool>& value)

   Writes the opposite of ``value``'s current value.

.. cpp:function:: RuleAction focus(Control& control)

   Gives ``control`` the keyboard focus (SurfaceRoot::request_focus on the firing window); a control that cannot take it is left as it is.

.. cpp:function:: RuleAction begin_keyboard_drag(Control& control)

   Enters ``control``'s keyboard drag mode (Control::begin_keyboard_drag), so that an application can bind its own move key; a control that declares no drag, or a window already running one, is left as it is.
